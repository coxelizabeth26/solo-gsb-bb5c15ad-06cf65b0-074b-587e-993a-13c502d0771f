# IPv4 子网规划台

一个纯本地的 IPv4 子网规划工具：在互不重叠的根网段中，以树形地址空间可视化管理命名保留段与子网分配，支持按主机数自动申请最小可用子网、**批量申请（逐行预演、整批原子加入）**、**静态主机地址编排（指定地址 + auto 自动安置，导出 hosts 文本）**、迁移预演、撤销重做、规划 JSON 导入导出与口令加密的备份导出/导入。

技术栈：**React 18 + TypeScript + Vite + ipaddr.js**，无任何后端依赖；规划以**修订图（revision graph）持久化在浏览器 localStorage**，并通过 **BroadcastChannel 在本机多个标签页之间协同编辑**；加密备份基于 **Web Crypto API**（PBKDF2-SHA-256 + AES-GCM-256）在浏览器内完成。

## 功能说明

### 根网段
- 添加多个**互不重叠**的根 CIDR（如 `10.0.0.0/8`、`192.168.0.0/16`），未对齐网络地址或相互重叠会被拒绝；
- 每个根网段显示地址总量与利用率进度条。

### 地址空间树
- 每个根网段以二叉树形式展示地址空间：`空闲`（绿色）、`部分占用`（黄色）、`已分配`（蓝色）；
- 空闲块自动按伙伴块（buddy）递归合并——释放分配后，可组成上级 CIDR 的相邻空闲块立即合并为更大的空闲节点；
- 部分占用的节点可展开/折叠，逐层下钻到具体分配。

### 分配
- **命名保留段**：指定名称 + CIDR，校验对齐、越界与重叠；
- **按主机数申请**：输入所需主机数，自动计算最小前缀（网络地址与广播地址不计入容量；/31 按 RFC 3021 计 2，/32 计 1），并在全部根网段（或指定根网段）中安置到**最低可用地址**；
- **批量申请**：「新建分配」面板的「**批量申请…**」弹窗中逐行填写**分配名称、主机数、可选根网段（自动/指定）与备注**；
  - 系统**按输入顺序**为每行计算最小前缀，并在指定根网段（或全部根网段）中寻找**最低可用地址**——前序行立即计入占用，后序行自动避开；
  - 弹窗实时预演并展示每行的**预分配 CIDR、可用主机容量、落位根网段与失败原因（带行号）**：名称为空、主机数非法、指定根网段不存在记为「非法」，空间不足记为「空间不足」；完全空白的行忽略；
  - **任一行非法或空间不足时禁止提交且不改变规划**；全部通过后所有分配以**一次可撤销修订原子加入**（一次撤销即整批回退）；
- 所有分配强制对齐 CIDR 边界，越界与重叠一律拒绝；
- 每条分配展示网络地址、广播地址、可用主机数与所属根网段。

### 生成 DHCP 地址池
- 分配清单中每个**子网**行提供「DHCP 池」操作，弹窗内逐行输入需排除的**单个 IPv4 地址或 CIDR**；
- 排除项必须**完整位于所选子网内**：任一行非法或越界时逐条列出错误（带行号），且不生成结果；
- 计算时 /0～/30 自动排除网络地址与广播地址，/31、/32 沿用可用主机规则（不额外排除）；
- 重叠或相邻的排除区间先合并，再以区间运算（非逐地址枚举）扣除，输出**最少数量**的「起始 IP - 结束 IP」连续范围；
- 结果可**一键复制**；该操作为纯本地计算，不修改规划、不产生历史记录。

### 生成反向 DNS 委派片段
- 分配清单中每个**子网**行提供「反向 DNS」操作，基于该 CIDR 生成**可复制的 BIND 委派片段**；
- 弹窗内逐行填写权威 NS（**每行一个，必须是带末尾点的绝对域名**，如 `ns1.example.com.`；**/32 可留空**）；任一非空行非法时按行报错（带行号）且**不生成结果**，非 /32 未填写 NS 同样不生成；
- 按前缀选择委派策略：

  | 前缀 | 生成内容 |
  | ---- | -------- |
  | /0、/8、/16、/24 | 单个 in-addr.arpa 区（如 `2.0.192.in-addr.arpa.`）及其父区 NS 委派 |
  | 其余 /1～/23 | 拆成**下一个八位边界**（/8、/16 或 /24）上的**最小区域集合**，逐区生成父区 NS 委派 |
  | /25～/31 | 按 **RFC 2317**：父区 NS 委派 + 覆盖子网**全部地址**的 CNAME + 子区名（`<首地址>-<末地址>.<父区>`） |
  | /32 | 单条 PTR 所有者提示（所有者名 + 所属 /24 区） |

- 结果**按数值地址升序**，分两段展示：**父区记录**（写入父区的 NS/CNAME）与**需创建的子区**（`zone` 声明及区文件 NS 注释），可**一键复制完整片段**；
- 该操作为纯本地计算，**不修改规划、不产生历史记录**。

### 静态主机地址编排
- 分配清单中每个**子网**行提供「**静态主机**」操作，弹窗内逐行填写**主机名 + 指定 IPv4 或 `auto`**（每行一台，空行忽略；主机名须为合法 LDH 主机名，可含点分标签）；
- 编排时**先整体预留所有合法指定地址**，再**按输入顺序**把 `auto` 安置到**最低可用主机地址**——前序 `auto` 不会抢占后续行指定的地址；
- 可用主机范围沿用现有规则：/0～/30 排除网络地址与广播地址，/31、/32 不额外排除；指定地址越界、落在网络/广播地址、主机名（大小写不敏感）或地址重复占用均记为「非法」，可用地址耗尽记为「空间不足」；
- 弹窗实时**逐行展示安置地址或失败原因（带行号）**；任一行非法或空间不足时**禁止导出**；全部通过后可**一键复制**并**下载**按地址升序的 hosts 文本（`IPv4 主机名` 每行一条）；
- 该操作为纯本地计算，**不修改规划、不产生历史记录**。

### 前缀策略校验
- 工具栏「**前缀策略校验**」入口打开弹窗，对当前所有**子网分配**（`kind = subnet`，命名保留段不参与）有序执行一段 prefix-list，模拟设备上的 `ip prefix-list` 放行/拒绝判定；
- 规则逐行书写，空行跳过：

  ```
  permit|deny CIDR [ge n le m]
  ```

  - `permit` / `deny` 为动作（小写）；
  - CIDR 必须**对齐网络地址**（如 `10.0.0.0/8` 合法，`10.0.0.1/8` 非法）；
  - 可选范围必须**同时**写为 `ge n le m`（顺序固定，不允许只写 `ge` 或只写 `le`），并满足 **CIDR 前缀 ≤ n ≤ m ≤ 32**；省略范围时**仅匹配同前缀**（相当于 `ge P le P`，P 为规则 CIDR 前缀）；
- 某个分配仅在**完整位于规则 CIDR 内**且**自身前缀落入 [n, m]** 时命中该规则；按规则书写顺序**首条命中**决定结论（permit/deny），全程未命中记为 **unmatched**；
- 任一非空行非法时**按行显示错误**（带行号）且不生成结果；规则区留空可执行（所有分配均 unmatched）；
- 成功后表格列出每个子网的**分配名称、CIDR、结论（permit/deny/unmatched）与命中行**（行号 + 规则原文），并汇总计数、可**一键复制文本报告**；
- 该操作为纯本地计算，**不修改规划、不撤销/重做历史**。

  示例：

  ```
  permit 10.0.0.0/8 ge 16 le 24
  deny 192.168.8.0/24
  permit 192.168.0.0/16 ge 16 le 23
  ```


### 迁移预演
调整根网段（编辑/删除）或分配容量时，系统先进行**迁移预演**：

1. **可保留项原位不动**（容量未变、仍在新根网段内且不与其他保留项冲突）；
2. 其余项按**网段从大到小、原地址升序**依次安置到**最低可用地址**；
3. 预演结果以表格展示（原位保留 / 迁移 / 无法安置）；
4. **存在无法安置项时确认按钮禁用**；否则确认后整批**原子应用**（单条历史记录，可一次撤销）。

### 撤销 / 重做
- 工具栏按钮或快捷键：`Ctrl/Cmd+Z` 撤销，`Ctrl/Cmd+Shift+Z` 或 `Ctrl+Y` 重做；
- 所有变更（含迁移、导入、清空、**撤销与重做本身**）均发布为一个新修订并进入历史栈。

### 本机持久化与多标签页协同
- 所有会改变 Plan 的操作都会生成一个**修订（revision）**：用 `crypto.randomUUID()` 生成 id，记录 `parentRevisionIds`、`clientId` 与**完整 Plan**，写入 `localStorage` 并更新 `head` 指针后通过 `BroadcastChannel` 广播；
- 新标签页打开（或刷新）时恢复 `head` 指向、且通过现有规划校验的修订；`head` 损坏时自动恢复到最近的完整叶子修订；
- 收到其他标签页的更新时**只按修订图的祖先关系**判定，绝不按时间戳覆盖：
  - 当前版本是收到修订的**祖先** → 自动**快进**，并在本页记为**一次可撤销变更**；
  - 收到修订是当前版本的**祖先**（过时/乱序更新）→ **忽略**；
  - 双方互不为祖先（修订图分叉）→ **两份都保留**并弹窗冲突；
- 冲突弹窗提供「**保留本页**」与「**采用外部**」：确认后生成一个**同时引用两个版本**的合并修订并继续广播，其他标签页收到后自动收敛；冲突期间**锁定一切规划编辑**（只读校验与导出仍可用），并挂起新到达的修订，合并后再统一重判（可能再次冲突）；
- 修订快照（含广播与本地存储）结构损坏或未通过规划校验时**忽略该快照并提示**，不影响其他修订；
- 空存储首次启动使用全局固定 id 的空规划创世修订，保证多个全新标签页自然收敛到同一节点。

### 导入 / 导出
- **导出**：下载当前规划为 JSON 文件；
- **导入**：选择 JSON 文件，完整校验（格式、对齐、根网段重叠、分配越界/重叠、容量一致性）通过后才替换当前规划，失败会列出全部错误；
- 「载入示例」可一键填充演示数据。

### 加密备份
- 工具栏「**加密导出**」：弹窗内**输入并确认口令**，使用 Web Crypto 生成**随机 16 字节 salt 与 12 字节 iv**，以 **PBKDF2-SHA-256 迭代 200000 次**派生 **AES-GCM-256** 密钥加密当前规划，下载**版本化 JSON 信封**：

  ```json
  {
    "format": "ipv4-subnet-planner/encrypted-backup",
    "version": 1,
    "kdf": { "name": "PBKDF2", "hash": "SHA-256", "iterations": 200000, "salt": "<Base64，16 字节>" },
    "cipher": { "name": "AES-GCM", "iv": "<Base64，12 字节>" },
    "ciphertext": "<Base64，含 GCM 认证标签>"
  }
  ```

- 工具栏「**加密导入**」：选择信封文件后输入口令解密。**仅接受上述信封**——字段缺失或 Base64 非法、版本不支持、口令错误、密文被篡改（GCM 认证失败）一律**拒绝并保持当前规划不变**；解密内容仍须通过现有 Plan 完整校验，成功后作为**一次可撤销修订**替换当前规划；
- 口令与派生密钥只存在于单次加解密调用中，**绝不写入 localStorage 等任何持久化存储**；口令遗忘后备份内容无法恢复。

## 容量计算规则

| 前缀 | 地址总数 | 可用主机 |
| ---- | -------- | -------- |
| /24  | 256      | 254      |
| /30  | 4        | 2        |
| /31  | 2        | 2（RFC 3021 点对点链路） |
| /32  | 1        | 1（主机路由） |

即常规前缀可用主机 = 2^(32-前缀) − 2（去掉网络地址与广播地址）。
